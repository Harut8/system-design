# ai-rag — Gap Analysis vs. the 2026 Agentic Stack

Audit date: 2026-10-10. This file compares what `ai-rag/` covers (chapters 00–08, 17, 20–25,
appendices D–H, four labs) against what production agentic systems look like in late 2026.
It is a **backlog**, not a chapter. Each gap lists where it should go so it lands in an existing
chapter where possible. Per the README's rule, write a gap up only when a project needs it.

Method: keyword sweep over every chapter (counts below), section-heading review of 06, 17, 20–25,
then web research on the current state of each area. Sources are at the bottom. Secondary-source
claims are marked *(verify)*.

---

## 1. MCP — the critical gap

**Why it matters.** MCP is now the default agent-to-tool contract. Anthropic donated it to the
Linux Foundation's Agentic AI Foundation (AAIF) in Dec 2025. Every major model vendor, IDE and
agent SDK speaks it. An "enterprise tool registry" design (`24` §5, `22` §13) that does not
mention MCP reads as 2024.

**What the folder needs** (one chapter, `26`):

- **Primitives:** tools, resources, prompts (server side); roots, sampling, elicitation
  (client side). Say which are deprecated in 2026-07-28 (roots, sampling, logging).
- **Transports:** stdio vs Streamable HTTP. SSE is legacy. The **2026-07-28 revision removes
  the `initialize` handshake and `Mcp-Session-Id`**: the core is stateless, and version and
  capabilities ride in `_meta` on each request. This is the most important change for scaling.
  MCP servers can now sit behind a plain L7 load balancer without sticky sessions.
- **Tasks extension** (`io.modelcontextprotocol/tasks`): long-running tool calls via
  `tasks/get` polling and `tasks/update`. Cancellation is cooperative. Map this onto `24` §11.3
  (submit → poll → retrieve), which already teaches the pattern without naming the standard.
- **MCP Apps:** server-supplied UI. Ties into the human-in-the-loop sections of `21` §6 and `22` §9.
- **Authorization:** OAuth 2.1 resource-server model. Protected Resource Metadata (RFC 9728)
  is mandatory. Client ID Metadata Documents are preferred and Dynamic Client Registration is
  deprecated. Also `iss` validation (RFC 9207) and audience-bound tokens (no token passthrough).
- **Registry and gateway:** the MCP Registry, and an MCP gateway as the policy enforcement
  point. This is `23`'s gateway pattern applied to tools. It is the natural place for RBAC,
  audit and rate limits.
- **Structured output:** `outputSchema` + `structuredContent`, plus tool annotations
  (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`).

**Concrete defect: `labs/tool-registry/mcp.py`.** Its docstring says MCP has *"no first-class
output/error schema or annotations field"* and *"no standardized authz"*. That stopped being
true in 2025: annotations arrived in 2025-03-26, `outputSchema`/`structuredContent` in
2025-06-18, and OAuth-based authorization in 2025-03-26, hardened since. Update the projection
to emit real `annotations` and `outputSchema` instead of folding hints into `description`.
Keep the "most-restrictive defaults on ingestion" rule: annotations are *hints from an
untrusted server*, so that rule is still correct.

## 2. A2A and the interop layer

- **A2A v1.0** (frozen Mar 2026 *(verify)*): Agent Cards (signed), tasks with lifecycle
  states, streaming, push notifications. It moved under AAIF in Aug 2026 *(verify date)*.
- The layering to teach: **MCP = agent→tool, A2A = agent→agent, AGENTS.md = repo→agent
  instructions.** `22` §5–6 teach multi-agent topologies only in-process. Add the
  *cross-process, cross-vendor* case and its failure modes: trust of a remote Agent Card,
  task ownership, and idempotency across an agent boundary.
- Interview angle: when an A2A boundary is warranted (separate team, deploy cadence or trust
  domain) vs when it is just a function call with extra latency.

## 3. Agentic security

`17` is excellent on prompt injection and already has the Rule of Two and CaMeL. What's missing:

- **OWASP Top 10 for Agentic Applications 2026** (published Dec 2025, ASI01–ASI10). It covers
  goal hijack, tool misuse, identity and privilege abuse, agentic supply chain, unexpected code
  execution, memory and context poisoning, insecure inter-agent communication, cascading
  failures, human-agent trust exploitation, and rogue agents. Map each to the `17` section that
  already defends it. Several (supply chain, inter-agent, cascading, rogue) have **no section**.
- **MCP-specific threats:** tool poisoning (instructions hidden in tool descriptions), rug-pull
  (a descriptor changes after approval, so pin a hash of the descriptor), tool shadowing and
  name collisions across servers, confused-deputy via token passthrough, and malicious
  community servers. The registry lab already has versioning (`evolution.py`), so a
  descriptor-hash pin is a small addition.
- **Memory poisoning:** a persisted fact (`25` §7) is a stored injection that fires in every
  later session. `25` §9.3 "superseding" needs a provenance/trust field on each memory.
- Also add the **OWASP LLM Top 10 (2025)** as the baseline map. `17` predates it in naming.

## 4. Agent identity and delegated authorization

`24` §6.3 covers OAuth token forwarding. Add:

- Agent as a **distinct principal**: user in `sub`, agent in `act` (RFC 8693 token exchange).
  Separate autonomous vs delegated actions. Use short-lived, down-scoped tokens (RAR, RFC 9396)
  and sender-constrained tokens (DPoP, RFC 9449).
- **Asynchronous consent** for background agents (CIBA), and step-up approval for destructive
  tools. That second part is the `22` §9.1 approval gate expressed as an auth flow.
- Standards status: agent-specific IETF drafts (WIMSE delegation, OAuth OBO-for-agents) are
  **not settled**. Build on the existing RFCs and say so.

## 5. Context engineering for agents

`06` covers context for a *RAG prompt*. The 2025–26 practice for *agents* is different and
absent:

- **Tool search / deferred tool loading.** Don't put 140 tools in the prompt (`22` Case 3
  already shows the pain); let the model search the catalog. `labs/tool-registry/discovery.py`
  already implements discovery, so connect the two.
- **Code execution over tools ("code mode").** Expose MCP servers as a code API in a sandbox,
  so intermediate data never passes through the context window. Anthropic reports large token
  cuts. Treat third-party percentages as claims.
- **Sub-agents for context isolation.** A sub-agent runs in a fresh window and returns a
  condensed result. This is the main reason to go multi-agent in 2026, and it differs from
  `22` §5's topology-driven reasons. Note the cost: multi-agent runs burn several times more
  tokens.
- **Agent Skills** (`SKILL.md` folders, progressive disclosure: name and description always
  loaded, body loaded on demand). A packaging format for procedural knowledge, adjacent to MCP.
- **Long-horizon compaction:** server-side compaction, context editing (clearing stale tool
  results), and file-based memory/notes. `06` §7 and `25` §3 cover summarization, but not the
  agent-loop variants.
- **Prompt-cache-aware agent loops.** `06` §12 covers caching. Add the agent rule: keep the
  tool list and system prompt stable, because dynamic tool injection busts the cache.

## 6. Agent runtime: sandboxes, harnesses, long-running sessions

There is no chapter on *where an agent runs*. Proposed `27`:

- **Harness vs model.** The same model scores very differently across scaffolds. Terminal-Bench
  2.0 lists 100+ agents on 23 scaffolds. The harness (loop, tools, context policy, retries) is
  the product.
- **Sandbox isolation tiers:** subprocess → container → gVisor → Firecracker/Kata microVM →
  sandbox-as-a-service. Include egress allow-lists, secret injection at the proxy (never in the
  sandbox), filesystem snapshots, and per-session ephemeral sandboxes. `17` §9.6 is the seed.
- **Long-running sessions:** session store, resume at the last safe point, and background
  agents with notifications. `21` §14 has a good LangGraph-vs-Temporal comparison. Generalize
  it to the agent runtime, and add the Agent SDKs (Claude Agent SDK, OpenAI Agents SDK, Google
  ADK) as "harness-as-a-library".
- Use `appendix-e` for the deploy substrate. This chapter is the agent-specific delta.

## 7. Agent observability (fold into planned `10`)

- OTEL GenAI semconv now defines **agent spans**: `create_agent`, `invoke_agent` (CLIENT for
  remote, INTERNAL for in-process), `execute_tool`, and workflow and MCP conventions. Status is
  still **Development**, so pin the semconv version. Content capture (prompts, tool args) is
  opt-in. Connect that to the PII line in `23` §9.1.
- Trace shape for a multi-agent run: a sub-agent is a child `invoke_agent`, and A2A crosses a
  trace boundary via W3C context propagation.

## 8. Agent evaluation (fold into planned `14`)

`08` already has `pass^k` (good). Add:

- **Public benchmark map**, read as *harness+model* scores: τ²-bench (dual-control tool use,
  DB-state graded), Terminal-Bench 2.0, SWE-bench Verified/Pro, GAIA, BrowseComp, OSWorld,
  BFCL (call validity only, not task success). Include each one's contamination and saturation
  caveats.
- **Environment-state grading** (check the DB or filesystem, not the transcript) as the default
  for action-taking agents.
- **Online eval:** sample production traces → judge → drift alerts. It closes the loop with `10`.
- **Simulated users** for multi-turn agents. Watch for simulator bias.

## 9. Framework landscape refresh (`22` §11)

`22` §11 compares LangGraph, CrewAI and AutoGen. As of 2026:

- AutoGen was merged into **Microsoft Agent Framework** with Semantic Kernel. Treat AutoGen as
  legacy.
- Missing entries: **OpenAI Agents SDK**, **Claude Agent SDK**, **Google ADK**, **Pydantic AI**,
  **Mastra** (TS), **smolagents** (code-agents).
- Re-cut the comparison on the axes that matter now: MCP/A2A support, durable execution,
  sandbox story, tracing semconv, lock-in. Drop axes that no longer differ.

## 10. Prompt and program optimization

Zero coverage of **DSPy** or **GEPA**, which are the mainstream way to tune multi-step prompts
against an eval set. This fits the folder's eval-first philosophy: an optimizer is a consumer of
the P0 golden set. Teach the failure mode with numbers. A 2026 case study saw train accuracy go
90→95% while held-out fell 95→85%. So a held-out split and the `08` significance machinery are
mandatory.

## 11. Memory products and benchmarks (`25`)

`25` teaches the right patterns. Add a short "landscape" subsection: Mem0, Letta (MemGPT),
Zep/Graphiti (temporal knowledge graph), and provider-native memory tools. Add memory
benchmarks (LoCoMo, LongMemEval) with the caveat that most published numbers are vendor
self-reports. Add the provenance field from §3 above.

## 12. Governance and regulation

`17` §10.2 maps regulation but never names the AI-specific regimes:

- **EU AI Act:** GPAI obligations applied from Aug 2025. The **Digital Omnibus (agreed
  May–Jun 2026)** moved stand-alone Annex III high-risk obligations from 2 Aug 2026 to
  **2 Dec 2027**, and Annex I product-embedded systems to 2 Aug 2028. Article 50 transparency
  dates are reported inconsistently *(verify against the Official Journal)*.
- **ISO/IEC 42001** (AI management system) and **NIST AI RMF + GenAI profile** as the
  control frameworks auditors ask for.
- Practical artifacts: an agent inventory, a tool-permission register, human-oversight records
  (the `22` §9 approval logs *are* this evidence), and incident logging.

## 13. Deliberately still out of scope

These are named so they don't creep in. They match the README §7 spirit:

- **Computer-use and browser agents.** Mention them as a tool class in `24`, plus a threat note
  in `17` (any page is an injection source). Don't write a chapter.
- **Voice and realtime agents.** A different latency discipline and stack.
- **RL fine-tuning of agents (RFT, GRPO).** Training work, already out of scope.
- **Agent payments (AP2, ACP).** Track only. Revisit if a project takes payments; PCI rules
  would apply.
